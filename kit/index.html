自走キットとは

AIコーディングエージェントに、プロジェクトの「運用」を任せるための設定一式です。人間が担当するのは、アカウント開設・貼り付け・設定変更・入金の受け取りなど、手を動かす作業だけ。企画・文面・制作・分析・毎日の指示出しはAIが行います。

毎日のループ（Brain 版 v1.1 の CLAUDE.md の要約）

  1. 起動時のフックの出力で、計画の要点・何日目か・残り日数・台帳の直近を確かめる
  2. 人間の報告があれば台帳（LEDGER.md）に記録する。数字は盛らない。無い数字は「-」
  3. 日付が今日以前でまだ判定していない判断ルールを照らし、結果を台帳に1行ずつ残す。発火したら計画を変える
  4. 今日の成果物（投稿文・記事・商品・分析）を作る
  5. 人間の作業を ops/dayNN.md に書く。コピペで済む粒度、順番つき、所要時間つき
  6. 投稿文は文字数を、商品文は禁止語を、スクリプトで確認してから渡す

向く人・向かない人

  • 向く：Claude Code を入れたが毎回の指示出しが手間で、日報・台帳・指示書まで任せたい人。個人開発や副業を「AIが回し、人間は手を動かす作業だけ」の分業で続けたい人
  • 向かない：収益や成果の約束を求める人。本キットは運用の型で、売上を約束するものではありません。作った私自身の挑戦も、このページを書いた 2026-10-18 の時点で売上 ¥0 です（毎日の数字は公開台帳）

確認した範囲と未確認

キットに入っている TESTLOG.md と、確認に使ったテストの記録から、事実だけを書きます。確認は 2026-10-16〜17 に、1台の macOS（26.6 系、bash 3.2、python3 3.9.6、Google Chrome 155、Claude Code 2.1.299）で行いました。

確認したこと

  • フック（v1・v1.1）：架空の小プロジェクト「14日で技術同人誌を1冊出す」のフォルダで Claude Code を非対話で起動し（claude -p）、デバッグの記録で SessionStart フックが動いたことを確かめた（v1・v1.1 とも終了ステータス0）。出力が文脈に入る形で渡されたことは、v1 の実行の記録で確かめた
  • スキルの読み込み（v1。結果を v1.1 の手引きに反映）：プロジェクトの .claude/skills から3本が読み込まれた。親フォルダに別の .claude/skills があるとそれも読み込まれ、git 管理下では読み込まれなかった → 手引きに「git init しておく」と追記
  • 起動する場所（v1。結果を v1.1 の手引きに反映）：サブフォルダで起動すると .claude/settings.json が読まれず、フックが動かなかった → 手引きに「最上位のフォルダで起動」と明記
  • モデルによる通し（v1.1・v1.2）：Sonnet のサブエージェントに、フックの出力と CLAUDE.md・スキル3本を手で読ませてから運用を任せた。確認スクリプトで v1.1 は17項目中16合格（FAIL 1・WARN 1）、v1.2 は17項目中15合格（FAIL 2件は、どちらも確認スクリプトが前の版の決まりのままだったことによる）。挙がった曖昧な点（15点と14点）を v1.2 と v1.3 で直した
  • lint.py（v1.1・v1.3）：止めるべき文22件・通すべき文14件の回帰テスト36件が、すべて期待どおりに判定された
  • xweight.py（v1.1）：ファイル先頭の1本の数え漏れ、→ や … の数え方、URL の直後に続く日本語の扱いを直し、直したあとの値を確かめた
  • scoreboard.py（v1.1）：表示名・目標・期限を引数どおりに入れた 1200×675 のPNGができた（macOS）
  • session-start.sh（v1.3）：前の版の型で作った README.md と、型をそのまま写した README.md の2つで実行し、欠けた項目の知らせ方がそれぞれ想定どおりだった。どちらも終了コード0
  • 配布物（v1.3）：Brain 出品文の「全ファイル」を見出しのパスどおりに書き出したものが、キットの23ファイルと同じ中身だった（diff で差分なし）
